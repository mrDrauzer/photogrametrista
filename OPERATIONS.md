# Шпаргалка по управлению (Cheat Sheet)

Данный файл содержит основные команды для управления и обслуживания инфраструктуры проекта.

## 🛠 Управление контейнерами

*   **Просмотр статуса всех сервисов:**
    ```bash
    docker-compose ps
    ```
*   **Запуск всех сервисов:**
    ```bash
    docker-compose up -d
    ```
*   **Остановка всех сервисов:**
    ```bash
    docker-compose down
    ```
*   **Перезапуск конкретного сервиса (например, Django):**
    ```bash
    docker-compose restart django-app
    ```
*   **Просмотр логов в реальном времени:**
    ```bash
    docker-compose logs -f django-app
    ```

## 🐍 Django и База данных

*   **Вход в shell Django:**
    ```bash
    docker-compose exec django-app python manage.py shell
    ```
*   **Создание суперпользователя:**
    ```bash
    docker-compose exec django-app python manage.py createsuperuser
    ```
*   **Применение миграций вручную:**
    ```bash
    docker-compose exec django-app python manage.py migrate
    ```
*   **Сбор статики вручную:**
    ```bash
    docker-compose exec django-app python manage.py collectstatic --noinput
    ```
*   **Вход в консоль PostgreSQL:**
    ```bash
    docker-compose exec postgres-postgis psql -U ${DB_USER:-diplom_user} -d ${DB_NAME:-diplom_db}
    ```

## 🚀 Масштабирование и обновление

*   **Масштабирование воркеров Celery:**
    ```bash
    docker-compose up -d --scale celery-worker=3
    ```
*   **Обновление кода (после git pull):**
    ```bash
    ./deploy.sh
    ```

## 🔍 Мониторинг и Логирование

*   **Grafana:** `http://your-ip:3000` (Логи в разделе Explore -> Loki)
*   **Prometheus:** `http://your-ip:9090` (Метрики)
*   **Проверка продления SSL:**
    ```bash
    docker-compose run --rm certbot renew
    ```

## 💾 Резервное копирование

*   **Ручной запуск бэкапа:**
    ```bash
    ./backup.sh
    ```
    *Дампы сохраняются в папку `./backups`*

## ⚠️ Решение проблем (Troubleshooting)

1.  **Контейнер падает с ошибкой:** Проверьте логи через `docker-compose logs <service_name>`.
2.  **Ошибка БД:** Убедитесь, что пароли в `.env` совпадают с теми, что использовались при первом запуске (инициализации тома `postgres_data`).
3.  **Nginx не стартует:** Возможно, не созданы SSL сертификаты. Используйте `./init-letsencrypt.sh`.

## 🧩 Frontend: «белый экран» на `/projects` (регрессии, которые легко вернуть)

Если на `/projects` виден пустой `#root` / белый экран — почти всегда причина в **критической JS-ошибке при рендере**.

### 1) `ReferenceError: kmlArtifacts is not defined`

**Где ломалось:** `frontend\src\components\map\MapView.jsx`

**Суть:** переменная для KML-артефактов должна называться **одинаково** в месте объявления и в JSX.

✅ Сейчас используется:
- `const kmlArtifacts = useMemo(() => results?.filter(r => r.type === 'kml') || [], [results]);`
- и далее `kmlArtifacts.map(...)` в JSX.

⚠️ Не переименовывайте только одну сторону (объявление или JSX) — это сразу вернёт «белый экран».

### 2) Leaflet + плагины (например, `leaflet-omnivore`)

**Где важно:** `frontend\src\main.jsx` и `frontend\src\components\map\MapView.jsx`

- Некоторые плагины ожидают, что Leaflet доступен глобально как `window.L`.
- ✅ Сейчас в `main.jsx` есть строка `window.L = L;` — **не удалять**.
- В `MapView.jsx` используется динамический импорт `import('leaflet-omnivore')` для предотвращения ошибок инициализации.

### 3) Видимость иконок в Dark Mode

**Где ломалось:** `MapDrawTools` в `MapView.jsx`

Если иконки на кнопках инструментов пропали (белое на белом) — проверьте, что:
- кнопки НЕ используют жестко заданный `bgcolor: 'white'` без явного задания темного цвета иконки.
- ✅ Рекомендуется использовать `bgcolor: 'background.paper'` и `color: 'text.primary'`, чтобы MUI автоматически адаптировал цвета под текущую тему (светлую или темную).

### 4) Если Django не запущен

**Где обработано:** `frontend\src\pages\ProjectPage.jsx`

Если бэкенд недоступен, страница проектов должна:
- не падать из-за необработанных ошибок запросов,
- показывать предупреждение (`Alert`) о недоступности API.

Если предупреждение исчезло / снова белый экран — проверьте, что:
- в `refreshData()` есть обработка `.catch(...)` для `fetchProjects()`
- и вспомогательные запросы (`templates`, `crs`, `categories`) не пробрасывают необработанные исключения.

### 5) Ошибка 500 при сохранении области (AOI)

**Где ломалось:** `core\serializers.py` (ProjectSerializer)

**Причина:** Django SpatialProxy ожидает объект `GEOSGeometry`, а не сырой словарь GeoJSON.

**Решение:** В методе `validate_area` добавлена принудительная конвертация словаря в `GEOSGeometry` через `GEOSGeometry(json.dumps(value))`. **Не удаляйте этот `json.dumps`**, иначе Django не сможет распарсить словарь.

### 6) Лаги карты и координаты курсора

**Проблема:** При обновлении координат курсора в общем стейте страницы весь UI (2000+ строк) перерисовывался 60 раз в секунду, вызывая жуткие тормоза.

**Решение:** Координаты вынесены в изолированный компонент `CursorDisplay` в `MapView.jsx`. 
⚠️ **Никогда не выносите состояние координат (`pos`) в родительский компонент `MapView` или `ProjectPage`!**

### 7) Инструменты рисования (MapDrawTools)

- **Семантика:** Все кнопки инструментов должны иметь `component="button"` (или быть реальными `<button>`). Если оставить `<a>` с `href="#"`, клик вызовет навигацию и сброс состояния SPA.
- **GeomanManager:** Вся логика `leaflet-geoman` находится в отдельном компоненте. Это сделано для реактивной активации режимов и предотвращения конфликтов с `FitBounds`.

### 8) Загрузка больших папок

В `nginx/nginx.conf` (в корне и в папке `nginx/`) параметр `client_max_body_size` должен быть не менее `100M` (а лучше больше для больших проектов). Если пользователь получает `413 Request Entity Too Large` при загрузке папки — проверьте этот конфиг.

### 9) Маркеры снимков (Clusters)

Если зеленые точки снимков пропали или выглядят как текстовые ссылки — проверьте импорты CSS в `MapView.jsx`:
- `leaflet.markercluster/dist/MarkerCluster.css`
- `leaflet.markercluster/dist/MarkerCluster.Default.css`
Без них кластеризация ломается визуально.

### 10) 3D Модель: 404 Not Found на demo_model.obj

**Проблема:** 3D вьювер показывает «Ошибка интерфейса» или не грузит модель, в консоли ошибка 404 для `artifacts/demo_model.obj`.

**Причина:** В демо-режиме (имитация обработки) создаются ссылки на файлы, которых может не быть на диске.

**Решение:** 
- Убедитесь, что в папке `media/artifacts/` существуют файлы `demo_model.obj` и `demo_ortho.tif`.
- В коде `core/tasks.py` добавлена автоматическая проверка и создание этих заглушек при завершении задачи.
- Если файлы удалены вручную, просто запустите любую задачу обработки заново (кнопка «Запустить обработку»), и они будут пересозданы.
- Фронтенд теперь имеет `ModelErrorBoundary`, который вместо крэша страницы покажет стандартную геометрическую фигуру (заглушку), если файл модели не загрузился.

### 11) Ошибка рендеринга на карте: `getNorth` of undefined
**Проблема:** Белый экран или крэш UI при открытии проекта, ошибка `Cannot read properties of undefined (reading 'lat')` в `getNorth`.
**Причина:** Попытка отобразить `ImageOverlay` с `bounds={null}` или невалидными координатами (например, если область проекта не задана, а результаты есть).
**Решение:** 
- Все `ImageOverlay` в `MapView.jsx` теперь обернуты в проверку `&& bounds`.
- Функция `isValidGeoJSON` усилена: теперь она проверяет не только структуру, но и то, что координаты являются валидными числами (`Number.isFinite`).
- В `FitBounds` добавлена проверка `bounds.isValid()`.
- **Никогда не передавайте `null` в проп `bounds` компонента `ImageOverlay`!**

### 12) Ошибка рендеринга на карте: `lat` of null
**Проблема:** Крэш UI, ошибка `TypeError: Cannot read properties of null (reading 'lat')` в `latLngToPoint`.
**Причина:** Попытка отрисовать маркеры, линии или кружки (`Marker`, `Polyline`, `CircleMarker`) с некорректными координатами (например, `[null, null]` или `NaN`).
**Решение:** 
- Всегда фильтруйте массивы координат перед передачей в компоненты Leaflet через `Number.isFinite`.
- ✅ В `MapView.jsx` добавлены фильтры для `heatmapData`, `gcps`, `flightPlans` и `annotations`.
- **Никогда не передавайте невалидные координаты в компоненты Leaflet!**

### 13) 3D Viewer: пустота или "данные не построены"
**Проблема:** В 3D режиме ничего не видно или отображается "заглушка" (синий узел), хотя обработка завершена.
**Причина:** Если в результатах нет объекта типа `3d` (MODEL_3D), вьювер показывает заглушку. Демо-файлы 1x1 или пустые .obj были невидимы.
**Решение:** 
- Добавлен режим «Только ортофото» (кнопка на странице проекта).
- Если 3D модель отсутствует, но есть ортофотоплан, `ModelViewer.jsx` автоматически отобразит его на горизонтальной плоскости в 3D сцене.
- Улучшена генерация демо-данных: теперь создаются видимые текстуры (зеленая сетка) и меши (плоскость 10x10м).

### 14) Просмотр результатов (Веб-интерфейс)
**Как быстро увидеть результат:**
- Во вкладке **«Результаты»** у каждого готового артефакта появилась кнопка **«ПОКАЗАТЬ»**.
- При нажатии система автоматически переключит режим (2D/3D), выберет нужный слой/модель и сфокусирует вид.
- Самые свежие результаты теперь автоматически выбираются при загрузке страницы или завершении задачи.

### 15) Публичный доступ (Public Share)
**Как это работает:**
- Ссылка формата `http://localhost:8080/share/<project_id>?token=<token>` позволяет просматривать проект без авторизации.
- Если проект защищен паролем, посетителю будет показан диалог ввода пароля.
- В публичном режиме скрыты все инструменты редактирования, управления файлами и задачами. Доступен только просмотр результатов и 4D мониторинг.

### 16) Улучшенная система ортофотопланов (WebODM & Tiles)
- **WebODM**: Полная интеграция с профессиональным движком WebODM для сшивки ортофотопланов и генерации DSM/DTM.
- **Тайлы (gdal2tiles)**: Теперь при создании ортофото автоматически генерируются тайлы в формате XYZ (Leaflet). Это позволяет плавно масштабировать огромные изображения.
- **Экспорт**: Доступен экспорт в форматах GeoTIFF, PNG, KMZ и Tiles (ZIP).
- **Название задачи**: При запуске обработки можно задать понятное имя для будущего результата.
- **Переименование**: Ортофотопланы можно переименовывать во вкладке «Результаты».

### 17) Хранение и просмотр результатов (Где лежат файлы?)
Все результаты обработки сохраняются в Docker-томе `media_volume`, который смонтирован в `/app/media/`.
- **Ортофотопланы и 3D модели**: `/app/media/artifacts/` (Доступны по URL `/media/artifacts/...`)
- **Тайлы (XYZ)**: `/app/media/tiles/` (Доступны по URL `/media/tiles/...`)
- **Сырые фото**: `/app/media/projects/` (Доступны по URL `/media/projects/...`)

Если вы хотите увидеть файл напрямую, используйте:
`http://localhost:8080/media/artifacts/<filename>`

### Быстрый чек-лист диагностики

1. Откройте DevTools → Console и найдите **первую** ошибку (она обычно первопричина).
2. Если ошибка про Leaflet/KML — проверьте `MapView.jsx` и `main.jsx` (см. пункты выше).
3. Если ошибки про сеть/`/api/` — убедитесь, что поднят `django-app` и прокси настроен (`nginx` проксирует `/api/`).
